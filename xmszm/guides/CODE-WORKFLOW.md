## 默认流程

代码开发任务默认遵循以下流程：

```
InitHook（环境检查）→ 定（项目定位）→ 查（归档定位，可选）→ 搜（兜底补充）→ 问（确认细节）→ 做（实施）→ 记（结果）
```

### 任务进度清单

复制此清单并跟踪进度：
```
任务执行进度：
- [ ] PreStep：InitHook（环境检查）
- [ ] Step 0：定（项目定位）
- [ ] Step 1：查（归档定位）
- [ ] Step 2：搜（兜底补充）- 如需要
- [ ] Step 3：问（确认细节）- 如需要
- [ ] Step 4：做（实施）
- [ ] Step 5：记（归档）
```

## PreStep：InitHook（环境检查）

> 📖 **初始化详情**：读取 `../templates/init-structure.md`

### 执行概要

1. 启动时检查 `.xmszm/` 是否存在
2. `.xmszm/` 不存在时继续执行，不强制初始化
3. 仅在明确开启归档模式时才初始化
4. 初始化仅允许修改 `.xmszm/` 与 `.gitignore`
5. 仅高风险场景询问用户（删除/跨项目写入/权限异常）

---

## Step 0：定（项目定位）⚠️ 优先执行

> 📖 **详细规则**：读取 `../rules/project-detection.md`
> 📖 **变量定义**：读取 `../rules/variables.md`

### 执行概要

1. 检测多项目环境（遍历一级子目录，查找项目标识文件）
2. 多项目环境：定位任务所属项目（路径提取/关键词匹配/交互选择）
3. 单项目环境：使用当前目录

### 输出变量

- `$PROJECT_ROOT`：项目根目录
- `$PROJECT_NAME`：项目名称
- `$ARCHIVE_PATH`：归档路径（通常为 `$PROJECT_ROOT/.xmszm`）

### 输出示例

「检测到多项目环境，本次任务定位到：`$PROJECT_NAME/`」

---

## Step 1：查（归档定位）

> 📖 **任务类型判断**：读取 `../rules/task-type-mapping.md`

### 执行概要

1. 读取 `$ARCHIVE_PATH/index.md`（如存在）
2. 根据任务关键词判断类型（页面/组件/API/数据库等）
3. 定位到对应归档文件并读取

### 输出示例

- 找到：「根据归档（`$ARCHIVE_PATH`），该功能位于 `src/views/Login.vue:15`」
- 未找到：「归档中未找到相关记录，将进行搜索」

### 跳过条件

- 用户明确说"不用看归档"
- 小改动快速模式（见下文 Fast Track）
- `.xmszm` 不存在或不可写

---

## Step 2：搜（兜底补充）

> 📖 **搜索策略**：读取 `../rules/search-strategy.md`

### 触发条件

- `$ARCHIVE_PATH` 不存在
- 归档中无相关记录
- 归档信息不完整

### 执行概要

- 优先使用本环境已可用工具（`rg`/`grep`/文件读取）
- 精确搜索使用 **Grep/Ripgrep**（已知类名/函数名）
- 文件查找使用 **Glob/Ripgrep files**（文件名模式）
- **强约束**：搜索限定在 `$PROJECT_ROOT`

---

## Step 3：问（确认细节）

### 执行概要

向用户确认关键信息（如有不确定之处）

### 跳过条件

- 用户已提供完整上下文
- 纯查询类任务
- Step 1 已定位成功且任务明确

---

## Step 4：做（实施）

正常执行任务，使用 TodoWrite 跟踪进度。

---

## Step 5：记（结果）

> 📖 **归档格式（可选）**：读取 `../rules/archive-format.md`

### 执行概要

1. 若 `.xmszm` 存在：更新功能归档与 changelog
2. 若 `.xmszm` 不存在：输出结构化变更摘要（任务/文件/类型/说明）
3. 多项目且启用归档时：更新根索引 `.xmszm/projects.md`

### 补记录规则

- 未记录的改动统一在 Step 5 补记
- “补记录”不触发初始化
- 无归档目录时，补记改为“输出摘要”而非“落盘”

### 跳过条件

- 未产生代码变更
- 用户明确说"不用记录"
- 临时调试且用户确认无需沉淀

---

## Fast Track（小改动快速模式）

满足以下条件可走快速模式：  
- 仅 1-2 个文件的小改动  
- 无架构调整、无跨模块改动  
- 用户明确要求快速交付  

快速模式流程：  
`定 → 做 → 记`  

说明：Fast Track 默认关闭，需显式确认后启用。

---

## 场景化流程参考

### 场景 1：单项目小改动
`定 → 做 → 记`

### 场景 2：单项目常规改动
`InitHook → 定 → 查 → 搜（按需）→ 问（按需）→ 做 → 记`

### 场景 3：多项目且已给路径
`定（路径提取）→ 查 → 做 → 记`

### 场景 4：多项目但未给路径
`定（交互选择项目）→ 查 → 搜（按需）→ 做 → 记`

### 场景 5：归档缺失
`直接继续主流程 → Step 5 输出结构化摘要`

### 场景 6：无可用语义检索工具
`查失败 → 使用 rg/grep + 文件读取组合定位`

### 场景 7：临时调试
`定 → 做 → 记（可由用户确认后跳过）`

### 场景 8：多人协作并发
`做 → 记（append）→ 冲突时 Git 人工合并`

## 初始化逻辑

> 📖 **初始化详情**：读取 `../templates/init-structure.md`

### 多项目环境

1. 根目录 `.xmszm/` 不存在 → 创建 `projects.md` 索引
2. 子项目 `$PROJECT_ROOT/.xmszm/` 不存在 → 创建完整归档结构

### 单项目环境

1. `.xmszm/` 不存在 → 创建完整归档结构

### 执行原则

以“最小侵入”为原则，默认静默初始化；仅高风险场景再询问，并追加到对应 `.gitignore`

---

## 边界情况

> 📖 **特殊场景处理**：读取 `../rules/edge-cases.md`

包含以下场景的处理策略：
- 任务涉及多个项目
- 无法自动定位项目
- 嵌套项目（不支持）
- 项目标识文件缺失
- .gitignore 冲突
- 归档目录不完整
- 文件损坏/格式错误
- 跨操作系统路径差异
- 用户中断初始化
- 归档文件过大
- 多人协作冲突
- 权限问题

## 完整示例：修改登录页样式

### 用户输入
```
修改登录页的样式为深色主题
```

### Step 0：定（项目定位）
```
检测到单项目环境
PROJECT_ROOT = E:\HundredsCompany\rule\xmszm
ARCHIVE_PATH = E:\HundredsCompany\rule\xmszm/.xmszm
```

### Step 1：查（归档定位）
```
读取 .xmszm/index.md
根据关键词"登录页"定位到 pages/login.md
找到相关记录：
  - 主文件：src/views/Login.vue:15-30
  - 样式文件：src/styles/login.scss:8-25
```

### Step 2：搜（兜底补充）
```
归档中已有记录，无需搜索
```

### Step 3：问（确认细节）
```
用户输入已清晰，无需确认
```

### Step 4：做（实施）
```
修改 src/views/Login.vue（深色主题相关代码）
修改 src/styles/login.scss（样式调整）
运行测试，确认无误
```

### Step 5：记（归档）
```
更新功能归档：pages/login.md
追加到 ## 最近变更 章节

更新 changelog：
- 新格式：changelog/2026-01/2026-01-07.md
- 旧格式：changelog/2026-01.md

多项目环境：更新 .xmszm/projects.md

完成记录
```
